# kiralearn.space Deployment Design

**Date:** 2026-05-08
**Status:** Approved — ready for implementation plan
**Domain:** kiralearn.space
**Repo:** `~/projects/kira-learn/` (currently uninitialized git)

## Goal

Take the existing local `/kira-learn` skill output (27 self-contained HTML articles) and turn it into a published indexed site at kiralearn.space, with a publish loop low-friction enough that Eli will actually keep using it.

Success criteria: after one new article is generated by `/kira-learn`, it is live at kiralearn.space within ~60 seconds with no manual deploy command.

## Non-goals

- No CMS, no markdown layer, no rewrite of existing articles
- No comments, no auth, no analytics beyond Vercel defaults
- No search in v1 (revisit after first 50 articles)
- No RSS in v1 (cheap to add later if needed)

## Architecture

```
~/projects/kira-learn/
├── articles/                  # 27 existing self-contained HTML files (untouched)
├── index.html                 # generated — clean grid homepage (Variant A)
├── sharp.html                 # generated — opinionated homepage (Variant C)
├── build-index.js             # scans articles/, regenerates both index pages
├── public/                    # favicon, og:image, robots.txt
├── vercel.json                # routing & headers
├── package.json               # node script + minimal deps
├── DESIGN.md                  # existing — design system source of truth
├── README.md                  # one-page operator readme
├── .gitignore
└── docs/superpowers/specs/    # this file lives here
```

Pure static. No framework. Vercel serves the folder.

## Components

### 1. Article metadata extraction

Each existing article has:
- `<title>...</title>` → article title
- `<p class="hook">...</p>` → one-line hook (used as excerpt)
- `<h1>...</h1>` → display heading

Date source: file `mtime`. Going forward, the `/kira-learn` skill will inject a `<meta name="article:published" content="YYYY-MM-DD">` tag so date is stable across machines and rebuilds.

Slug = filename minus `.html`. URL = `/articles/{slug}`.

No edits to existing 27 articles required. The build script handles missing `<meta>` by falling back to mtime.

### 2. `build-index.js`

Pure Node, zero non-stdlib dependencies (regex parsing of the small set of tags above; no JSDOM needed). Runs in <100ms over 27 files.

Inputs: scan `articles/*.html`.
Outputs: write `index.html` (Variant A) and `sharp.html` (Variant C).

Both pages share the same DESIGN.md tokens (Inter, dark `#08090a`, accent `#5e6ad2`/`#7170ff`).

### 3. Variant A — `/` clean grid

- Header: site name "Kira Learn", short subtitle ("Notes on the systems behind tools you use")
- Article grid: 3 columns desktop, 2 tablet, 1 mobile
- Each card: title, date (relative — "3 days ago"), one-line hook
- Hover: card lifts subtly, accent border
- Footer: link to `/sharp`, link to GitHub repo

### 4. Variant C — `/sharp` opinionated

The pick: **typographic feed**. Concretely:
- Single column, max-width ~720px, centered
- Each entry: title at clamp(28px, 4vw, 44px) in Inter 600, hook below at 16px muted, date in a `tabular-nums` small caps at 12px to the side or above title
- Vertical rhythm: ~64px gap between entries, hairline divider (`rgba(255,255,255,0.06)`) between them
- No cards, no grid, no hover lifts — only a subtle accent underline animation on title hover
- Reads like a curated journal, not a blog feed

Footer: link to `/`, link to GitHub repo.

### 5. Skill integration

Update `~/.claude/skills/kira-learn/SKILL.md`. After writing the article HTML, add:

```bash
cd ~/projects/kira-learn
node build-index.js
git add articles/{slug}.html index.html sharp.html
git commit -m "Add: {title}"
git push
```

Failure modes the skill must handle (note: skill runs non-interactively under Claude Code, so "surface error" means write a clear message to stderr and include it in the skill's final response):
- `git push` fails (offline, auth) → commit stays local, error printed in skill output, recovery is `cd ~/projects/kira-learn && git push`
- `build-index.js` fails → article HTML is still on disk and committable; error printed; recovery is `node build-index.js && git add . && git commit --amend --no-edit && git push`
- `node` not on PATH → skill should detect and report; do not attempt to commit a stale index

### 6. Vercel + DNS

One-time setup steps (these go in the implementation plan, not the spec):
1. `git init` + initial commit + push to GitHub repo
2. `vercel link` from project root
3. Vercel dashboard → add `kiralearn.space` as production domain
4. Update DNS at registrar (exact records come from Vercel's "Domains" panel — do not hardcode IPs in the plan; copy from dashboard at setup time):
   - Apex `kiralearn.space` → A record (IP shown in Vercel dashboard)
   - `www.kiralearn.space` → CNAME `cname.vercel-dns.com`
5. Vercel issues TLS automatically

`vercel.json`:
- `cleanUrls: true` so `/articles/foo` works without `.html`
- Cache headers:
  - `/articles/*` → `Cache-Control: public, max-age=31536000, immutable` (article HTML is rewritten only when the slug changes, never edited in place)
  - `/`, `/sharp` → `Cache-Control: public, max-age=300, must-revalidate` (regenerated on every push, want the new article to appear within ~5 min even if a CDN edge missed the deploy invalidation)

## Data flow

```
/kira-learn skill
   │
   ├─► writes articles/{slug}.html
   ├─► runs node build-index.js
   │       └─► regenerates index.html + sharp.html
   ├─► git add → commit → push
   │
   └─► GitHub
          │
          └─► Vercel webhook → build (no-op for static) → deploy
                 │
                 └─► live at kiralearn.space (~30-60s)
```

## Error handling

| Failure | Behavior |
|---|---|
| Article HTML write fails | Skill aborts, no commit |
| `build-index.js` parse error on one article | Skip that article, log warning, continue |
| `git push` fails | Leave commit local, surface error, do not retry silently |
| Vercel deploy fails | GitHub shows red check; user sees notification email from Vercel |

## Testing

Targeted, not exhaustive:

1. **build-index.js**: snapshot test — run against current 27 articles, assert both output pages contain expected count of links and one known title
2. **Article metadata extraction**: unit test the regex extraction against a fixture HTML with all three tags, one with missing `<meta name="article:published">`, one with malformed HTML
3. **End-to-end smoke**: after deployment, `curl https://kiralearn.space/` returns 200 and contains a known article title

No CI in v1 — these are local smoke tests. Vercel handles the deploy itself.

## Decisions captured

- **Pure static + Node build script** chosen over Astro because each article is already a complete styled HTML page; a content layer would be overhead for zero benefit.
- **Two homepage variants shipped together** so Eli can compare on real content; one becomes `/` after a week of use.
- **Auto-commit + push from skill** chosen over manual gate because the friction goal is "actually use it." Auth/network failures are surfaced but don't block article creation.
- **Date via injected `<meta>` going forward, mtime fallback for existing 27**: avoids retroactively editing the existing articles while giving stable dates for new ones.
- **No search in v1**: 27 articles is browsable; search is justified at ~50+.

## Open questions

None blocking. Possible v2: RSS feed, search, tag pages, dark/light toggle.

## Out of scope for this spec

- Migrating existing self-contained article styles into a shared stylesheet (would break the "self-contained" property the skill depends on)
- A separate admin/CMS interface
- Multi-author support
